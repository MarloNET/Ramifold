## ADR-003 – Anbindung von Claude Code als unveränderter CLI-Prozess; Chat-Transkript bei Ramifold

- **Slug:** `claude-code-integration`
- **Status:** **approved (Gate „Wie“ Slice 0.1, MAR-1369; Owner-Freigabe 2026-11-25 mit „Stimmt“ bei allen 13 kritischen Annahmen; freigegebene Revision `e24de893-855d-43a5-8c04-2c0257b1fd7d`)**. Stand bei der Prüfung: Vorgeschlagen. Den Teil „offiziell unterstützte Anmeldung“ entscheidet der Owner mit Gate „Wie“ (Baseline-Briefing, „Deine Entscheidungen“), weil Frage 3 der zurückgezogenen Karte `e4597c5b` unbeantwortet blieb. Technisch ist der Weg bei beiden Antworten derselbe; die Antwort ändert nur Dokumentation und Datenabfluss-Hinweis. Zwei Grundsätze hat der Owner am 2026-11-25 entschieden: Vorschläge und Zusammenfassungen zweigen die Chat-Sitzung ab (Variante b, schon in Slice 0.1, mit Rückfall; übermittelt in MAR-1414), und eine Sitzung wird nur fortgesetzt, wenn sie den ganzen Chat kennt, dauerhaft je Sitzungseintrag geprüft (Variante a zu TS-R-12; übermittelt in MAR-1416). Die Ausgestaltung durch die Agenten (Bedingungen im Einzelnen, stiller Rückfall, kein Hinweis bei veralteter Sitzung) ist bis zur Freigabe von Gate „Wie“ Vorschlag (H-12). Owner-Entscheidung am 2026-11-25: Variante a (Empfehlung der Baseline).
- **Kontext:** LP-04 (KI über den Coding-Agenten des Nutzers), LP-05 (Nutzungsbedingungen, keine Grauzone), OQ-01, A-12 (API-Key-Weg = Claude Code mit API-Key-Anmeldung), REQ-018/REQ-029 (Chat unabhängig von Sitzungen), REQ-035 (aktueller Kontext), REQ-065 Nr. 8 (weitere Agenten).
- **Primärquelle (gelesen am 2026-11-24):** Claude Code Docs, „Legal and compliance“, https://code.claude.com/docs/en/legal-and-compliance. Kernaussagen: OAuth-Anmeldung der Abos ist für die normale Nutzung von Claude Code bestimmt. Entwickler von Produkten, auch mit dem Agent SDK, *sollen* API-Keys nutzen. Verboten ist, in eigenen Apps einen Claude.ai-Login anzubieten, Anfragen im Namen ihrer Nutzer über Abo-Zugangsdaten zu leiten oder Zugangsdaten bzw. Sitzungs-Token zu sammeln, zu speichern oder zu vermitteln. Ausdrücklich nicht eingeschränkt ist, dass ein Endnutzer das **unveränderte Claude-Code-Binary mit seinem eigenen Abo** anmeldet, auch wenn eine Plattform Claude Code betreibt. Dort genannte Bedingungen für Produkte, die Claude Code ausführen: Binary nicht verändern, keine Anmeldeart entfernen, Nutzung nicht bezahlen, weiterverkaufen oder vermitteln, jeder Endnutzer meldet sich selbst an.
- **Optionen:**
  1. **Unverändertes `claude` des Nutzers als Kindprozess** (`claude -p`, `stream-json`), Ramifold fasst keine Zugangsdaten an.
  2. **Claude Agent SDK** in Ramifold eingebettet – nach der Primärquelle ein „Produkt mit dem Agent SDK“, für das API-Keys erwartet werden; Abo-Nutzung wäre die Grauzone, die LP-05 ausschließt.
  3. **Direkte Anthropic-API** – widerspricht LP-04 und A-12 (0.5).
- **Entscheidung (Vorschlag):** Option 1. Ramifold startet den vom Nutzer installierten Befehl `claude` ohne Änderungen, mit dessen eigener Anmeldung. Empfohlen ist, Abo-Login und API-Key offiziell zu unterstützen; die Entscheidung trifft der Owner mit Gate „Wie“. Ramifold fragt keine Zugangsdaten ab, liest keine, speichert keine und leitet keine weiter; es setzt keine Anmelde-Umgebungsvariablen. Ramifold ist kostenlos und vermittelt keine Nutzung. Mindestversion **v2.1.248** (wegen `--restricted`, ADR-004).
  - **Transkript bei Ramifold:** Jede Nachricht wird von Ramifold im Chat gespeichert (REQ-018). Die Claude-Sitzung ist nur Beschleuniger: Sie wird fortgesetzt, solange der Kontext-Fingerabdruck gleich ist, sie den ganzen gespeicherten Chat kennt und Claude Code sie kennt. Ob sie den Chat kennt, prüft Ramifold dauerhaft: Der Sitzungseintrag merkt sich die letzte Chat-Nachricht, die die Sitzung kennt, und sie muss die letzte maßgebliche Nachricht des Chats sein (v0.7, Owner-Entscheidung a vom 2026-11-25; z. B. passt sie nicht mehr, wenn der Chat am anderen Rechner weiterging). Sonst startet eine neue Sitzung mit gespeichertem Verlauf (REQ-029, REQ-035); den Hinweis „Sitzung neu aufgebaut“ gibt es nur, wenn Claude Code die Sitzung nicht fortsetzen kann. Sitzungseinträge sind rechnerbezogen und liegen in `.ramifold/local/sessions.json`.
  - **Abzweigung für Vorschläge und Zusammenfassungen (v0.6, Owner-Entscheidung b vom 2026-11-25):** Passt die gespeicherte Chat-Sitzung des Knotens (gleicher Fingerabdruck, Sitzung kennt den ganzen Chat, dieselbe dauerhafte Prüfung wie bei der Fortsetzung), zweigt Ramifold sie ab (`--resume <id> --fork-session`), damit der Prompt-Cache greifen kann; die Abzweigung wird nicht gespeichert, Chat und Chat-Sitzung bleiben unverändert (REQ-037, REQ-041). Sonst, und nach „Sitzung unbekannt“ genau einmal, läuft eine neue einmalige Sitzung mit dem Chatverlauf aus Ramifold. Einzelheiten: Technical Specification Abschnitt 2.8.
  - **Anbieterneutrale Schnittstelle:** `agent-gateway` spricht über `AgentPort` mit einem Adapter `claude-code`; weitere Adapter (andere Coding-Agenten, API-Key direkt) folgen in 0.5 ohne Datenänderung. **Abzweigen ist eine optionale Fähigkeit des Adapters (`capabilities.canForkSession`), kein Teil des Pflichtvertrags von `AgentPort`; ohne sie laufen Vorschläge und Zusammenfassungen in einer neuen einmaligen Sitzung mit dem Chatverlauf aus Ramifold.** So bleibt ein weiterer Anbieter ohne Umbau möglich, denn der Chatverlauf liegt anbieterneutral bei Ramifold, und Sitzungen sind nur Beschleuniger, je Agentenart gespeichert.
  - **Prüfung und Fehlerzuordnung (v0.3, Cross-Check B1, B3, CC-05):** Version per `claude --version` beim Start (parallel, nicht blockierend) und erneut vor jeder KI-Anfrage, solange der letzte Befund `not_found` oder `too_old` ist. Weil jede Anfrage einen neuen Prozess startet, ist nach `claude update` kein Neustart von Ramifold nötig; nur ein Befehl in einem neuen Suchpfad-Eintrag braucht einen Neustart aus einem neuen Terminal. Die Anmeldung prüft Ramifold nicht vorab (es liest keine Anmeldedaten). Authentifizierungsfehler von Claude Code, ob nie angemeldet oder abgelaufen, ordnet der Adapter dem einen Code `not_authenticated` zu; der nächste Schritt ist in beiden Fällen derselbe. Weist Claude Code eine schon gespeicherte Nachricht vor der Antwort ab (`not_authenticated`, Prozess startet nicht), erhält die Nachricht den Status `not_sent` und kann erneut gesendet werden. Alle Ursachen-Codes: Baseline Abschnitt 9.
- **Folgen:** Abhängig vom Ausgabeformat `stream-json` und von Startoptionen von Claude Code; deshalb kapselt der Adapter beides, und Tests nutzen einen simulierten Claude Code (REQ-064). Claude Code legt eigene Sitzungsprotokolle unter `~/.claude/` ab, auch eine Datei je Abzweigung (Baseline Abschnitt 8, R-03). Der Kostenvorteil der Abzweigung ist nicht garantiert (Technical Specification TS-R-10, bewusst akzeptiert).
- **Risiken:** Anthropic ändert Regeln oder Optionen (R-01). Wird der Abo-Login für Werkzeuge wie Ramifold untersagt, bleibt der API-Key-Weg ohne Umbau (A-12). Fehlertexte zur Anmeldung ändern sich (R-09); die Zuordnung ist im Adapter gekapselt und getestet.
- **Umkehrbarkeit:** mittel (Adapter austauschbar; Transkript-Prinzip schwer).
