## ADR-004 – Werkzeugfreigabe der KI als konfigurierbare Richtlinie; Plan-Zugriff als späterer MCP-Server

- **Slug:** `tool-policy-and-plan-access`
- **Status:** **approved (Gate „Wie“ Slice 0.1, MAR-1369; Owner-Freigabe 2026-11-25 mit „Stimmt“ bei allen 13 kritischen Annahmen; freigegebene Revision `e24de893-855d-43a5-8c04-2c0257b1fd7d`)**. Stand bei der Prüfung: Vorgeschlagen (setzt Owner-Hinweis 1 aus `gate-wie-hinweise` an MAR-1355 um)
- **Owner-Hinweis (wörtlich):** „Die Werkzeugfreigabe der KI (Skills, MCP-Server, Schreib- und Ausführrechte) wird als konfigurierbare Berechtigung entworfen, mit Bestätigung vor ändernden oder ausführenden Aktionen (LP-03). Ramifolds Plan-Zugriff wird so geschnitten, dass er später als eigener MCP-Server angeboten werden kann. In 0.1 wird nichts davon gebaut (REQ-024 bleibt).“
- **Kontext:** REQ-022 bis REQ-025, REQ-034, LP-03, A-01, OQ-08; Entwurfsfälle des Owners: (a) Skill im Knoten-Chat, (b) Ramifold-MCP für Plan lesen, später ändern, (c) GitHub-MCP für Issues mit Bestätigung vor jeder Aktion.
- **Primärquellen (gelesen am 2026-11-24):** Claude Code Docs „CLI reference“ (`--restricted`, `--tools`, `--allowedTools`, `--disallowedTools`, `--permission-mode`, `--strict-mcp-config`, `--mcp-config`, `--disable-slash-commands`, `--settings`, `--permission-prompt-tool`) und „Configure permissions“ (Arbeitsverzeichnisse, `permissions.blockReadsOutsideWorkingDirectories`, Grenzen der Read-Regeln). `--restricted` (ab v2.1.248): „removes the built-in tools that run commands or code, and WebFetch, unless you name them individually in `--tools` … confines the built-in file tools to the working directories, loads only managed settings and `--settings`, refuses `bypassPermissions`“. Read-Verbote gelten für die eingebauten Dateiwerkzeuge, nicht für Shell-Unterprozesse; diese sind hier nicht freigegeben.
- **Optionen:**
  1. **`ToolPolicy` als Datenobjekt**, das der Adapter in Startoptionen übersetzt; 0.1 hat genau eine feste Richtlinie.
  2. Feste Startoptionen im Code, später umbauen.
  3. Eigene Abschottung (Container, Sandbox) für die Lesebeschränkung.
- **Entscheidung (Vorschlag):** Option 1.
  - **`ToolPolicy`** beschreibt: eingebaute Werkzeuge (erlaubt / mit Bestätigung / verboten), Lese-Bereich, Skills (aus / Liste), MCP-Server (keine / Liste mit Werkzeugen und Stufe), Web-Domains (alle / Liste). Der Adapter `claude-code` übersetzt sie in Startoptionen.
  - **0.1, feste Richtlinie „read-only-planning“:** `--restricted`, `--tools` = `Read,Glob,Grep,WebSearch,WebFetch`, dieselben als erlaubt, `--permission-mode dontAsk`, `--strict-mcp-config` ohne MCP-Konfiguration, `--disable-slash-commands` (keine Skills), `--settings` mit `permissions.blockReadsOutsideWorkingDirectories: true` und Lese-Verbot für `./.ramifold/**`; Arbeitsverzeichnis = Projektordner. Damit sind REQ-022, REQ-023, REQ-024 und REQ-025 erfüllt; OQ-08 ist beantwortet: verlässlich für alle Dateiwerkzeuge.
  - **Später (nicht in 0.1):** Bestätigung vor ändernden oder ausführenden Aktionen über `--permission-prompt-tool` mit einem Werkzeug des Ramifold-MCP-Servers, das die Frage als Bestätigungsdialog im Browser stellt und auf den Planer wartet (LP-03). Fall (a): Skill in der Richtlinie freischalten, ohne ändernde Werkzeuge. Fall (b): Ramifold-MCP-Server als Aufrufer von `plan-service` (lesen sofort, ändern nur mit Bestätigung). Fall (c): GitHub-MCP-Server in der Richtlinie mit Stufe „Bestätigung vor jeder Aktion“. Strukturierte Rückfragen (OQ-04) werden ein weiteres Werkzeug desselben MCP-Servers.
  - **Plan-Zugriff:** `plan-service` ist die einzige Schnittstelle zu Vorhaben, Knoten, Ergebnissen und Kontext; `http-api` ist heute ihr einziger Aufrufer. Kein anderer Teil liest `.ramifold/` direkt.
  - **Künftige konfigurierbare Freigabe (v0.3, Cross-Check CC-01; Entwurf, in 0.1 nicht gebaut, keine Bedienung, kein Screen; REQ-024 bleibt):**
    - **Geltungsbereich:** eine Grundrichtlinie je Projektordner (gilt für die Instanz) und optional eine Richtlinie je Vorhaben, die die Grundrichtlinie für dieses Vorhaben ersetzt. Keine Knotenebene; sie ließe sich später additiv ergänzen. Ohne eigene Einstellung gilt die feste Richtlinie „read-only-planning“, die im Code steht und nicht in einer Datei.
    - **Speicherort:** rechnerbezogen in `.ramifold/local/tool-policy.json`, durch `local/.gitignore` nie in Git, auch nicht als versionierter Vorschlag. Grund: Ein `git pull` aus einem fremden Repo oder Branch darf der KI nie Schreib- oder Ausführrechte verschaffen. Folge: Auf einem zweiten Rechner gibt der Planer Freigaben neu. Fehlt die Datei oder ist sie unlesbar, gilt die feste Richtlinie (im Zweifel weniger Rechte).
    - **Rückfrage:** Bei Stufe „mit Bestätigung“ fragt Claude Code vor **jedem einzelnen** ändernden oder ausführenden Werkzeugaufruf über `--permission-prompt-tool` beim Ramifold-MCP-Server nach. Ramifold stellt die Frage **im Fenster, das die KI-Anfrage gestellt hat**, mit Werkzeugname und vollständigen Argumenten; andere Fenster sehen nur die laufende Anfrage. Keine Sammelfreigabe („für diese Sitzung merken“) in der ersten Ausbaustufe. **Als abgelehnt gilt** die Rückfrage, wenn der Planer ablehnt, das auslösende Fenster geschlossen wird oder seine Verbindung verliert, kein Fenster verbunden ist, eine Zeitgrenze abläuft (Wert im späteren Slice), die Anfrage abgebrochen oder Ramifold beendet wird. Während die Rückfrage offen ist, läuft die KI-Anfrage weiter (höchstens eine je Instanz, REQ-069); die Inaktivitätsgrenze ruht.
    - **Zustände für das spätere Design:** nicht freigegeben, freigegeben, freigegeben mit Bestätigung; je Rückfrage: offen, bestätigt, abgelehnt, abgelaufen, Fehler (z. B. MCP-Server nicht erreichbar, wird wie abgelehnt behandelt).
    - **Rückkanal:** Der Ramifold-MCP-Server läuft als Kindprozess von Claude Code und spricht über `127.0.0.1` mit `ramifold-server`. Weil die lokale API keine Zugangstokens hat (ADR-007), bekommt er ein Geheimnis je KI-Anfrage, das nur `ramifold-server` und dieser Prozess kennen. Einzelheiten im Slice, der die Freigabe baut.
- **Folgen:** Mindestversion von Claude Code v2.1.248. Die KI sieht eigene Skills, MCP-Server und Einstellungen des Nutzers in Ramifold nicht (A-01). Der Ramifold-Bereich ist für die KI unlesbar.
- **Risiken:** Verhalten von `--restricted` ändert sich (kritische Annahme 1, R-01); Prompt-Injection über WebFetch (R-02, bewusst akzeptiert; später Domain-Liste).
- **Umkehrbarkeit:** leicht (Richtlinie ist Daten).
